# План MVP — что делаем в первой версии

> Этот документ фиксирует упрощения относительно полной спецификации
> ([bot-spec.md](bot-spec.md)): цель MVP — быстро получить работающего бота
> на бесплатных компонентах, а «правильную» инфраструктуру докрутить потом.

## 1. Скоуп MVP

**Делаем:**

1. Бот принимает `t.me/username`, `t.me/s/username` или `@username` (а также пересланный из канала пост).
2. Данные собираются **только парсингом публичной веб-страницы** `https://t.me/s/<username>` — без Telethon, без user-аккаунтов, без риска бана.
   - Одна страница отдаёт ~20 постов; дописывая `?before=<id>`, догружаем историю (по умолчанию до 100 последних постов).
   - Доступно: текст поста, дата, просмотры, реакции по эмодзи, ссылка на пост, признак репоста, тип медиа. Метаданные канала: название, описание, число подписчиков.
3. Анализ — через **OpenRouter, только бесплатные модели** (суффикс `:free`):
   - батч-классификация постов (полезный / нейтральный / шум, категория, реклама, репост);
   - синтез итоговой сводки (автор, о чём канал, развитие, что забрать себе, топ-посты, красные флаги, вердикт).
4. Отчёт в Telegram (1–2 сообщения) + кнопки «🔄 Обновить» и «👍/👎».
5. Кэш отчётов в SQLite (TTL 7 дней), суточный лимит на свежие анализы (по умолчанию 5/день на пользователя — бережём лимит ключа OpenRouter).

**НЕ делаем в MVP (оставляем на v1):**

- Telethon / MTProto, приватные каналы, комментарии linked-чатов;
- PostgreSQL, Redis, отдельная очередь воркеров (в MVP — фоновые asyncio-задачи в процессе бота + SQLite);
- история «Мои анализы», динамика между срезами, сравнение каналов, веб-страницы, монетизация.

## 2. Лимиты OpenRouter и как мы в них вписываемся

- Free-tier (ключ без пополнений): **50 запросов/день, 20 запросов/мин** на все `:free`-модели.
- После разового пополнения на $10 лимит становится **1000 запросов/день** (остаётся навсегда) — это первый апгрейд, если упрёмся.
- Бесплатные модели живут на волонтёрских мощностях и могут отдавать 429 → в коде заложены:
  - **fallback-список моделей** (если одна недоступна/перегружена — идём к следующей);
  - ретраи с экспоненциальной паузой;
  - понятная ошибка пользователю, если легли все.

**Бюджет запросов на один свежий анализ:** ~4–5 LLM-вызовов
(3–4 батча классификации по 25 постов + 1 синтез).
С кэшем 7 дней: на бесплатном ключе ≈ 10 свежих каналов в день, повторные открытия — бесплатно.

Список моделей задаётся в `.env` (модели меняются — актуальные смотреть на
openrouter.ai/models с фильтром «Free»). Дефолты — крупные модели с хорошим русским:
`deepseek/deepseek-chat-v3.1:free`, `meta-llama/llama-3.3-70b-instruct:free`,
`qwen/qwen-2.5-72b-instruct:free` и т.п.

## 3. Архитектура MVP

```
Telegram ──► aiogram-бот (thbot/bot.py)
               │  валидация ссылки, кэш, лимиты
               │  фоновая asyncio-задача + статус-сообщение
               ▼
        ┌──────────────────────┐     ┌──────────────────────────┐
        │ parser.py            │     │ analyzer.py              │
        │ httpx + BeautifulSoup│     │ OpenRouter (OpenAI SDK)  │
        │ t.me/s/<name>        │     │ L1 классификация батчами │
        │ + пагинация ?before  │     │ L2 синтез сводки (JSON)  │
        └──────────┬───────────┘     └────────────┬─────────────┘
                   ▼                               ▼
              storage.py (SQLite): кэш отчётов, лимиты, фидбек
                   │
                   ▼
        report.py → готовый текст отчёта → пользователю
```

Никаких внешних сервисов кроме Telegram и OpenRouter: запускается на любом VPS/домашней машине одной командой.

## 4. Структура кода

```
thbot/
  config.py    — настройки из .env (токены, модели, лимиты)
  parser.py    — сбор канала с t.me/s (есть CLI для проверки: python -m thbot.parser <username>)
  analyzer.py  — вызовы OpenRouter, промпты, разбор JSON
  report.py    — сборка текста отчёта (HTML для Telegram)
  storage.py   — SQLite: кэш, лимиты, фидбек
  bot.py       — aiogram-хендлеры и фоновые задачи (точка входа: python -m thbot.bot)
```

## 5. Запуск (локально / на VPS)

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env        # вписать BOT_TOKEN и OPENROUTER_API_KEY
python -m thbot.bot
```

- Токен бота: @BotFather.
- Ключ OpenRouter: openrouter.ai/keys (бесплатно, карта не нужна).

Проверка парсера без Telegram и без LLM:

```bash
python -m thbot.parser molyanov_blog
```

## 6. Что докручиваем после MVP (по убыванию важности)

1. **Telethon-коллектор**: полная история, форварды, комментарии — точнее метрики и «развитие».
2. **История анализов** пользователя и diff «что изменилось» при обновлении.
3. **Калибровка рубрики** полезности по фидбеку 👍/👎.
4. Вынос воркера в отдельный процесс (очередь), если станет много пользователей.
5. Приватные каналы (бот-админ), сравнение каналов, шеринг отчёта ссылкой.
