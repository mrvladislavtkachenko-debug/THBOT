# THBOT — Telegram-бот для анализа каналов

> Спецификация продукта (PRD + техническое ТЗ). Версия 0.1 — черновик для старта разработки.

---

## 1. Идея одним абзацем

Пользователь присылает боту ссылку на любой Telegram-канал (или `@username`). Бот собирает посты канала и его метаданные, прогоняет их через LLM-анализ и возвращает структурированную сводку: **кто автор**, **о чём канал и как он развивался**, **какой контент полезный, а какой — шум**, и **что конкретно можно забрать себе** (идеи, практики, инструменты, форматы постов). По сути — «досье» на канал за 1–2 минуты вместо часа ручного скролла.

Рабочее название: **THBOT** (Telegram Helper Bot).

---

## 2. Проблема и ценность

В Telegram тысячи каналов, и понять, стоит ли подписываться и что из канала можно взять, можно только пролистав ленту вручную. Это долго, и глаз «замыливается» рекламой, репостами и мемами.

**Ценность для пользователя:**

- за 1–2 минуты получить объективную картину канала вместо субъективного первого впечатления;
- понять, кто за каналом стоит (эксперт, аноним, команда, медиа);
- отделить зерна от плевел: какие посты — реальная польза, какие — наполнитель;
- получить готовый список «выносной пользы»: практики, инструменты, форматы контента, которые можно применить у себя.

**Типичные применения:**

- оценка канала перед подпиской / покупкой рекламы / взаимопиаром;
- ресерч конкурентов и ниш авторами своих каналов;
- поиск работающих форматов контента и тем для заимствования;
- проверка собственного канала «со стороны» (для авторов).

---

## 3. Целевая аудитория

| Сегмент | Что хочет получить |
|---|---|
| Авторы Telegram-каналов | разбор конкурентов, рабочие форматы, темы постов, оценка своего канала |
| Маркетологи / закупщики рекламы | адекватен ли канал, есть ли живая аудитория, не закредитован ли рекламой |
| Обычные пользователи | стоит ли подписываться, не «вода» ли это |
| Продуктовые/контент-команды | мониторинг ниши, сравнение каналов (v2) |

---

## 4. Глоссарий

- **Канал** — Telegram-канал (broadcast), публичный (`@username`, `t.me/username`) или приватный (ссылка-инвайт `t.me/+hash`).
- **Пост** — сообщение в канале: текст, медиа, реакции, репосты, счётчик просмотров.
- **Индекс полезности** — агрегированная оценка канала 0–100: доля и «вес» полезного контента с учётом вовлечённости.
- **Выносная польза (takeaways)** — конкретные вещи, которые пользователь может применить: практики, инструменты, гайды, форматы.
- **Коллектор** — компонент, который собирает посты и метаданные канала.
- **Анализатор** — компонент на базе LLM, который классифицирует и суммирует контент.

---

## 5. Пользовательские сценарии (user stories)

1. **Быстрая оценка.** Пользователь кидает `t.me/some_channel` → через ~1–2 минуты получает сводку с оценкой и решает, подписываться или нет.
2. **Ресёрч конкурента.** Автор канала кидает ссылку на канал конкурента → получает разбор: темы, форматы постов, частота, что собирает больше всего реакций, что можно позаимствовать.
3. **Проверка перед рекламой.** Маркетолог кидает ссылку → видит долю рекламных постов, активность аудитории (просмотры/реакции/репосты), подозрение на накрутку.
4. **Самоанализ.** Автор кидает свой канал → получает объективный разбор: что работает, что провисает, советы по развитию.
5. **История.** Пользователь возвращается в бот и смотрит ранее проанализированные каналы (кнопка «Мои анализы»).
6. **Обновление.** Пользователь запрашивает канал, который уже анализировали неделю назад → бот либо отдаёт кэш, либо предлагает «Обновить анализ».

## 6. Пользовательский флоу (UX)

```
/start
  └─ приветствие + краткая инструкция: «Пришлите ссылку на канал или @username»

Пользователь: t.me/durov
  ├─ Бот валидирует ссылку
  ├─ Если канал есть в кэше (TTL 7 дней):
  │     → сразу отчёт + кнопка «🔄 Обновить анализ»
  └─ Если нет:
        → «🔎 Анализирую канал @durov…» (статус-сообщение обновляется):
           1. «Собираю посты…»
           2. «Анализирую контент (это займёт ~1 мин)…»
           3. «Формирую отчёт…»
        → Отчёт (одно длинное сообщение или несколько + кнопки)

Кнопки под отчётом:
  [🔄 Обновить] [📊 Мои анализы] [⭐ Полезный пост: ссылка(и)]
  [👍 Точно / 👎 Мимо] — фидбек на качество анализа
  [📤 Поделиться отчётом]
```

**Состояния ошибок:**

- не ссылка / не канал → «Это не похоже на ссылку на канал. Пример: `t.me/username`»;
- приватный канал без доступа → «Приватный канал. Чтобы я мог его прочитать, добавьте бота в канал админом (или пришлите инвайт-ссылку) — появится в v1/v2»;
- канал не существует / забанен → понятное сообщение;
- пустой/мёртвый канал (< N постов за период) → «Канал слишком мал/неактивен для анализа»;
- перегрузка/таймаут → «Сервис занят, анализ поставлен в очередь, пришлю результат».

## 7. Функциональные требования

### 7.1. Ввод и валидация

- Принимать: `https://t.me/username`, `t.me/username`, `@username`, `https://t.me/+invitehash`, пересланный пост из канала (из `forward_origin` извлекать канал).
- Распознавать несколько ссылок в одном сообщении (анализировать первую / предложить выбор).
- Отсекать: ссылки на пользователей, ботов, группы, чаты, внешние сайты.
- Нормализовать всё к `@username` / инвайт-хэшу.

### 7.2. Сбор данных (коллектор)

Источники — по приоритету (см. также раздел 13):

1. **MTProto (Telethon/Pyrogram) на user-аккаунте** — основной источник для публичных каналов:
   - метаданные: название, описание, число подписчиков, дата создания (косвенно), закреплённые сообщения, linked-чат;
   - история постов: текст, медиа-тип, дата, просмотры, форварды, реакции (по типам), ответы/комментарии;
   - сигналы о рекламе: наличие `#реклама`, пометки спонсоров, частота внешних ссылок.
2. **Веб-превью `t.me/s/username`** — fallback без авторизации: HTML последних постов (обычно ~20–100). Дёшево, но хрупко и без полных метрик.
3. **Бот-админ в канале** — для приватных каналов (v2): Bot API отдаёт посты канала, где бот состоит.

**Параметры сбора (MVP):** последние 200–300 постов или все посты за 90 дней (что меньше).

**Сохранять сырой срез в БД** — это позволяет:
- считать динамику при повторных анализах (как менялось число постов/вовлечённость);
- не переплачивать LLM за повторный анализ;
- строить историю развития канала.

### 7.3. Предобработка

- Дедупликация (репосты одного и того же внутри канала, альбомы → один пост).
- Очистка: служебные сообщения, навигационный мусор; нормализация текста.
- Извлечение признаков: длина поста, наличие медиа/ссылок/хэштегов/опросов, язык, время публикации, день недели.
- Батчинг постов для LLM (по 10–25 постов в промпте в зависимости от длины).

### 7.4. LLM-анализ

Двухуровневый пайплайн:

**Уровень 1 — классификация постов (быстрая/дешёвая модель):**
для каждого поста:
- категория: гайд/инструкция, кейс/разбор, инсайт/мнение, новость, реклама, репост, мем/развлечение, цитата/мотивация, анонс/организационное, оффтоп, опрос;
- оценка полезности: `0` — шум, `1` — нейтральное, `2` — полезное;
- теги/темы (финансы, IT, маркетинг…);
- есть ли прикладной экшен (что можно сделать после прочтения);
- признаки рекламы/нативки/взаимопиара.

**Уровень 2 — агрегация и синтез (сильная модель):**
на вход — метаданные канала + агрегаты по постам + топ-посты целиком; на выход — структурированный отчёт (раздел 8):
- профиль автора и канала;
- хронология развития и динамика;
- ключевые темы и их доли;
- топ полезных постов (с ссылками на них);
- выносная польза: практики, инструменты, форматы контента;
- красные флаги (реклама, накрутка, копипаста, мёртвый чат);
- итоговая оценка и вердикт.

Результат обоих уровней — строго JSON по схеме (см. раздел 10), чтобы из него детерминированно собирать отчёт.

### 7.5. Классификация «полезно / бесполезно»

Прозрачная рубрика (заложена в промпт, видна пользователю в отчёте):

**✅ Полезное:**
- гайды, инструкции, туториалы, чек-листы, шаблоны;
- разборы реальных кейсов и ошибок;
- оригинальные инсайты, аналитика, данные, исследования;
- подборки инструментов/ресурсов с пояснением, как применять;
- экспертные ответы на вопросы аудитории;
- эксклюзивный опыт автора (чего нет в открытом доступе).

**⚠️ Нейтральное:**
- анонсы, организационные посты, опросы, авторские новости ниши.

**❌ Шум / бесполезное:**
- реклама и нативные интеграции, взаимопиар;
- репосты чужих постов без комментария;
- мемы, развлечение, мотивационные цитаты «ни о чём»;
- дубли новостей, которые и так везде;
- флуд, оффтоп, пустые опросы-активаторы;
- копипаста из других каналов/источников.

**Индекс полезности (0–100):** взвешенная доля полезных постов
(вес поста = полезность × нормированная вовлечённость: реакции + репосты + комментарии относительно просмотров и медианы по каналу).
Дополнительно считать: **индекс рекламы**, **индекс оригинальности** (доля не-репостов), **регулярность** (постов в неделю, стабильность), **вовлечённость** (ER по реакциям/репостам/комментариям).

### 7.6. История и кэш

- Кэш отчёта на канал: TTL 7 дней; хранить версии отчётов, чтобы показывать «что изменилось с прошлого анализа».
- «Мои анализы»: список каналов пользователя с датой и оценкой, кнопка «открыть отчёт».
- Лимиты free-tier: например, 3 анализа в день на пользователя (настраивается).

### 7.7. Фидбек

- Кнопки 👍/👎 под отчётом + текстовый комментарий; сохранять в БД для калибровки промптов и рубрики.

### 7.8. Админ-функции (v1+)

- /stats: число пользователей, анализов, доля ошибок, расход токенов;
- ручной бан/разбан, изменение лимитов;
- логи ошибок коллектора и LLM.

## 8. Структура отчёта (что видит пользователь)

Примерный шаблон (финальный текст генерирует LLM, но структура фиксированная):

```
📊 СВОДКА ПО КАНАЛУ «Название канала» (@username)

🔗 t.me/username · 👥 48 000 подписчиков
📈 Постов в неделю: ~4 · 🗓 Канал с 2021 г.

━━━━━━━━━━━━━━━━━━━
👤 АВТОР
Имя/псевдоним, кто по контенту (позиция, опыт, бэкграунд —
из описания, закрепа и контента). Один человек / команда / аноним.
Насколько экспертность подтверждается контентом (кейсы, детали,
личный опыт vs пересказ чужих мыслей).

📚 О ЧЁМ КАНАЛ
Ниша, ключевые темы (с долями): продуктовый дизайн 40%,
карьера 25%, ... Тон и стиль: личный/медийный, плотность текста,
много/мало медиа.

📈 РАЗВИТИЕ
Как канал менялся: рост частоты, смена тем, ребрендинг,
появление рекламы, динамика вовлечённости (по доступным данным).
Регулярность, «живость» аудитории.

━━━━━━━━━━━━━━━━━━━
🎯 ИНДЕКС ПОЛЕЗНОСТИ: 74/100
👍 Полезного контента: ~65% постов
📢 Реклама/пиар: ~12%  · 🔁 Репосты: ~8%
💬 Вовлечённость: высокая (ER 4.2%)
🚩 Красные флаги: всплеск рекламных постов в последний месяц

🧰 ЧТО МОЖНО ЗАБРАТЬ СЕБЕ
1. Формат «разбор недели»: короткие выводы с пруфами — собирает
   максимум репостов. Ссылка на пример: t.me/c/.../123
2. Рубрика «инструмент недели» — шаблон поста: проблема →
   инструмент → как внедрить за 15 минут.
3. Гайд по X (шаблон чек-листа, 3 части): t.me/c/.../145
4. Практика: разборы собственных провалов — самые вовлекающие посты.

🔥 ТОП-5 ПОЛЕЗНЫХ ПОСТОВ
1. [Название/тема] — 12k 👁, 340 🔁 — t.me/...
2. ...

⚠️ СЛАБЫЕ СТОРОНЫ
Много мемов в будни по вечерам, падающие просмотры на длинных
постах, участие в взаимопиарных «подборках».

✅ ВЕРДИКТ
Крепкий экспертный канал с оригинальным контентом; подписаться
стоит, читать выборочно — ссылки на лучшее выше.
```

Отчёт собирается из JSON-данных + сгенерированных формулировок; числа и доли — только из реально посчитанных метрик (LLM не «выдумывает» цифры).

## 9. Методология оценки (как считаем метрики)

| Метрика | Как считается |
|---|---|
| Индекс полезности | Σ(полезность поста 0/1/2 × вес вовлечённости) / максимум, шкала 0–100 |
| Доля рекламы | посты с вердиктом «реклама/пиар» / все посты |
| Оригинальность | не-репосты / все посты |
| Вовлечённость (ER) | (реакции + репосты + комментарии) / просмотры, медиана по постам |
| Регулярность | среднее и std интервалов между постами; постов/неделю по неделям |
| Подозрение на накрутку | аномально высокие просмотры при низких реакциях/репостах относительно ниши; резкие скачки просмотров; отключённые реакции |
| Динамика | сравнение срезов во времени (нужны повторные сборы); для первого анализа — внутренняя динамика по периодам (первые 30 дней выборки vs последние) |

## 10. Контракт LLM-анализа (JSON-схемы)

**Уровень 1 — на каждый батч постов:**

```json
{
  "posts": [
    {
      "id": 123,
      "category": "guide | case | insight | news | ad | repost | meme | quote | announcement | offtop | poll",
      "usefulness": 0,
      "tags": ["product_design", "career"],
      "has_actionable": true,
      "is_ad": false,
      "is_repost": false,
      "reason": "краткое обоснование вердикта, до 15 слов"
    }
  ]
}
```

**Уровень 2 — итоговый отчёт:**

```json
{
  "channel_handle": "username",
  "niche": ["дизайн", "продукт"],
  "author": {
    "name": "...",
    "type": "personal_expert | personal_anon | team | media",
    "background": "...",
    "expertise_evidence": "..."
  },
  "development": {
    "history_summary": "...",
    "frequency": "4 поста/нед, стабильно",
    "trend": "growing | stable | declining",
    "notes": "..."
  },
  "scores": {
    "usefulness_index": 74,
    "ad_ratio": 0.12,
    "originality_ratio": 0.88,
    "engagement_rate": 0.042,
    "red_flags": ["рост рекламы за последний месяц"]
  },
  "takeaways": [
    {"title": "Формат «разбор недели»", "how_to_use": "...", "example_post_url": "t.me/..."}
  ],
  "top_posts": [
    {"post_url": "t.me/...", "topic": "...", "views": 12000, "forwards": 340}
  ],
  "verdict": "..."
}
```

Правила промптинга:
- цифры подставляются кодом, LLM работает только с текстами и агрегатами;
- strict JSON / structured outputs; при ошибке парсинга — 1 повтор, затем фолбэк на текстовую сводку без чисел;
- температура 0.2–0.4 для воспроизводимости;
- язык отчёта — язык канала (для русскоязычных каналов — русский).

## 11. Технический стек (рекомендуемый)

| Слой | Технология | Почему |
|---|---|---|
| Язык | Python 3.12 | экосистема для Telegram и LLM |
| Бот-интерфейс | **aiogram 3.x** (async) | актуальный, удобные FSM/инлайн-кнопки |
| Сбор данных | **Telethon** (MTProto, user-аккаунт) + парсер `t.me/s/` как fallback | Bot API не читает чужие каналы |
| LLM | OpenAI (GPT-4o/4o-mini) или Anthropic Claude; дешёвая модель для классификации, сильная для синтеза | structured outputs, контроль стоимости |
| Очередь/фоновые задачи | **arq** (async Redis) или Celery | анализ длится 1–3 мин, нельзя блокировать хендлер |
| БД | **PostgreSQL** (asyncpg + SQLAlchemy 2) | каналы, посты-срезы, отчёты, пользователи, лимиты, фидбек |
| Кэш/брокер | **Redis** | кэш отчётов, очередь, rate-limit |
| Инфра | Docker Compose, VPS (2 vCPU / 2–4 GB минимум), вебхук или long-polling | дёшево для старта |
| Метрики/логи | structlog + (опц.) Grafana/Loki | следить за расходом токенов и ошибками |

Альтернативы: python-telegram-bot вместо aiogram; Pyrogram вместо Telethon; SQLite на старте MVP (но лучше сразу Postgres).

## 12. Архитектура

```
┌──────────────┐   update    ┌────────────────────┐

```

## 13. Ограничения Telegram — критично знать до старта

1. **Bot API НЕ умеет читать историю произвольных каналов.** Бот видит только то, что приходит ему в чаты, где он состоит. Поэтому для сбора нужен **MTProto-клиент на user-аккаунте** (Telethon/Pyrogram, `api_id`/`api_hash` с my.telegram.org) либо парсинг публичного веба `t.me/s/username`.
2. **User-аккаунт для парсинга — серая зона ToS Telegram.** Митигация: отдельный номер/аккаунт, низкие частоты запросов, уважение FloodWait, кеширование, fallback на `t.me/s`. На этапе MVP можно вообще начать с `t.me/s` (без рисков для аккаунта), Telethon добавить в v1.
3. **Приватные каналы:** user-аккаунт должен состоять в канале (может вступить по инвайт-ссылке) либо бот добавлен админом. Это v2.
4. **Детальная статистика** (прирост подписчиков, графики Telegram Stats) доступна только админам канала. Для публичных каналов довольствуемся: подписчики, просмотры, реакции, форварды, комментарии linked-чата, даты постов. Историю динамики копим сами повторными сборами.
5. **Лимиты и скорость:** анализ канала = десятки запросов к Telegram + 20–60 тыс. токенов LLM. Отсюда: очередь, статус-сообщение, кэш, суточные лимиты на пользователя.
6. **Стоимость LLM:** классификацию делаем дешёвой моделью (mini/haiku-класс) батчами, синтез — сильной. Грубая оценка: один анализ ~$0.02–0.10 в зависимости от модели и глубины.

## 14. Нефункциональные требования

- **Производительность:** время до первого статус-сообщения < 2 c; полный анализ ≤ 3 мин (целевое — 60–90 c).
- **Надёжность:** ретраи к Telegram и LLM с экспоненциальной задержкой; задача не теряется при рестарте воркера (persistent очередь); пользователь всегда получает результат или понятную ошибку.
- **Стоимость:** кэш 7 дней; лимиты на пользователя; дешёвая модель для классификации; алерт при аномальном расходе токенов.
- **Приватность:** хранить только публичные данные каналов и telegram id пользователей; не хранить переписку пользователей сверх необходимости; возможность `/delete_my_data`.
- **Масштабирование:** воркеры горизонтально (несколько процессов arq); один Postgres/Redis на старте.
- **Языки:** MVP — русский + английский (автоопределение языка канала).

## 15. Риски и митигация

| Риск | Митигация |
|---|---|
| Бан/флуд user-аккаунта Telethon | отдельный аккаунт, низкий rate, паузы на FloodWait, fallback `t.me/s`, кэш |
| LLM галлюцинирует (выдумывает факты/цифры) | цифры считает код; strict JSON; промпт «только на основе предоставленных постов»; фидбек 👎 для калибровки |
| Канал с медиа без текста | учитывать подписи к медиа; помечать как медиа-формат; не падать |
| Накрученные каналы искажают метрики | эвристики накрутки (просмотры/реакции), флаг «подозрение на накрутку» |
| Долгий анализ → пользователь ушёл | живой статус + результат приходит отдельным сообщением даже если чат закрыт |
| Стоимость LLM при вирусном росте | free-лимиты, кэш, дешёвая модель, позже — монетизация |

## 17. Метрики успеха

- **Retention:** доля пользователей, сделавших ≥2 анализа за неделю;
- **Конверсия в шеринг:** доля отчётов, которыми поделились;
- **Качество:** доля 👎 фидбека < 10%; ручная выборочная проверка точности классификации (цель ≥ 85% совпадений с человеком);
- **Технические:** успешных анализов > 95%, медианное время < 90 c;
- **Юнит-экономика:** стоимость анализа < цены тарифа с запасом ×3.
